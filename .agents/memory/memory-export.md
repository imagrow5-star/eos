---
name: Memory export ("download your journal", Sprint E)
description: The single user-triggered export pipeline — every user-data table flows through one loader; new tables must join it
---
- **One loader, one choke point.** `fetchExportPayload(userId, range)` in `routes/account.ts` is the single place that queries every user-owned table and decrypts every encrypted column (raw SQL bypasses drizzle's customType mappers, so it calls `decryptText`/`decryptJson`/`decryptTextArray` by hand). Both exports flow through it: the legacy `/account/export` (JSON + styled HTML report) and the Sprint E `/api/memory/export`. **A new user-data table must be added there** (and to the deletion sweep in `auth.ts` + the account-export coverage guards) or it silently misses every export.
- **Two export surfaces, do not confuse them.** `/account/export?format=json|html` = the original flat dump + printable HTML report (has date-range `?from/&to`, no rate limit). `/api/memory/export?format=json|markdown` (Sprint E) = a cleaner nested/portable JSON (`export_metadata`/`profile`/`memory.facts`/…) + a warm Markdown "memoir"; rate-limited 1/hour/user; no date range (always full history).
- **Presentation is pure + unit-tested.** `services/memoryExport.ts` holds `shapeMemoryExport` / `renderMemoryMarkdown` / `memoryExportFilename` — pure functions of the loader payload (no DB/clock/I-O), so `memory-export-format.test.ts` pins the JSON shape, memoir section order, and filename with no DB. The route (`routes/memory.ts`, `GET /memory/export`) only wires loader → shaper/renderer → headers.
- **Rate limit lives in `middleware/usageLimits.ts`** (`memoryExportUsageLimits`, env `MEMORY_EXPORT_LIMIT_PER_HOUR`, default 1). Keys per user via `sessionUserKey`. `setup/rate-limit-env.ts` sets it high so integration suites can export repeatedly; `memory-export-rate-limit.test.ts` sets it to 1 BEFORE importing the app to exercise the 429 (same dynamic-import pattern as `usage-limits.test.ts`). Because it's 1/hour, the Settings UI rests both download buttons after one success rather than inviting a guaranteed-fail second click.
- **Non-negotiables baked in:** read-only (only SELECTs — never mutate on export); every encrypted column decrypted to the user's OWN plaintext (that's the point); `crisis_events` are metadata only (detected_at/country/source — never `pattern_matched` or content, Tier 1); `subscription` is tier/status/dates only (no Paddle ids); logs carry `hashUserIdForLog(userId)` as `uh` + format, never a raw userId or payload (Tier 3 guardrail).
- Filename is compact date: `eos-memory-export-YYYYMMDD.{json,md}` (no dashes) — differs from `/account/export`'s dashed `eos-export-YYYY-MM-DD.json`.
- `profile.email` comes from the `users` row (not `profile`), fetched by a small `fetchAccountBasics` join in the route — `fetchExportPayload`'s profile query has no email. Internal serial `id`s are deliberately omitted from the memory export.
