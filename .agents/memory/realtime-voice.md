# Realtime voice architecture

**Rule:** Voice calls try the ElevenLabs Conversational AI agent first (native mic streaming, turn-taking, barge-in); the browser SpeechRecognition + sentence-TTS "classic" engine is the automatic fallback, never removed. Claude remains the only brain: the agent's LLM is configured as a Custom LLM pointing at our OpenAI-compatible endpoint (`/api/voice-llm/v1/chat/completions`), which rebuilds the full persona/memory system prompt server-side and ignores the agent-config system prompt.

**Why:** ElevenLabs owns the hard realtime problems (latency, VAD, interruption) far better than our hand-rolled loop, but the product's soul is the persona + user memory — that must never fork into a second prompt maintained in the ElevenLabs dashboard.

**How to apply:**
- Auth on the custom-LLM endpoint is ONLY the HMAC token (`userId.iat.exp.env.sig`, SESSION_SECRET-signed) that the session endpoint mints and the client passes via `customLlmExtraBody` → arrives as `body.elevenlabs_extra_body.user_token`. The endpoint is public (ElevenLabs servers call it) — never weaken the token check; 401 on any failure.
- **Tokens are ENV-TAGGED (July 2026):** payload carries `"prod"` (when `REPLIT_DEPLOYMENT` is set) or `"dev"`; verify rejects a mismatch. Why: dev and prod share SESSION_SECRET but have SEPARATE databases with overlapping user ids — an untagged dev token hitting prod's endpoint would load a real production user's memories on id collision. Consequence: realtime calls from the workspace preview fail (visibly) at the first turn, because the agent's Custom LLM URL is the production endpoint — voice calls are tested end-to-end in the PUBLISHED app.
- The token's `issuedAt` doubles as the call-start marker: prompt context = DB messages `createdAt < issuedAt` + the in-call turns ElevenLabs sends. Never mix in rows persisted during the call or turns duplicate.
- In-call turns are persisted fire-and-forget; ElevenLabs resends the conversation each turn, so persistence dedupes the latest user turn (interruption resend) — keep that guard.
- Claude alternation invariants: merge consecutive same-role turns, drop a leading assistant turn, and if history ends with assistant, synthesize/merge a user turn.
- `ELEVENLABS_AGENT_ID` secret gates the feature; unset → session endpoint returns `available:false` → client shows a note and uses classic mode.
- Frontend engine discipline: `voiceEngineRef` ("realtime"|"classic"|null); every classic-mode callback (TTS onStart/onEnd, handleSpeak, tap-to-interrupt/speak UI) must guard against running while realtime is active — the agent owns all audio. On call end/unmount/disconnect: `endSession()`, null the convo ref, invalidate the messages query (voice turns appear in chat history).
- Realtime callbacks need SESSION-IDENTITY gating, not just ref guards: a gen counter bumped at every call start AND end, captured per-attempt; every SDK callback (onMode/onUserText/onAgentText/onDisconnect/onError) and every post-await checkpoint compares it. Otherwise a delayed onDisconnect from an ended session passes the ref guards and tears down the next call (end→quick-restart race).
- ElevenLabs API keys are permission-scoped: a key without convai_* scopes makes get-signed-url 401 `missing_permissions` (get-signed-url specifically needs `convai_write`, not just read). The session endpoint must return that as a SPECIFIC reason (`api_key_permission`, `api_key_invalid`, `agent_not_found`, `elevenlabs_unreachable`) and NEVER silently downgrade to public-agent mode — that was the July 2026 "click → nothing" bug. Public mode is attempted only when no API key exists at all. Browser-side failures (WS close reasons, SDK errors) POST to `/api/voice-agent/client-error` → server logs; disconnect causes render on-screen.
- **Agent config is API-managed now (key has convai_write since July 2026)** — no dashboard round-trips: `PATCH /v1/convai/agents/{id}` deep-merges nested partials (verified: sibling fields survive). Current wiring: `prompt.llm="custom-llm"`, `prompt.custom_llm.url="https://eos-companion.replit.app/api/voice-llm/v1"` (base only — ElevenLabs appends `/chat/completions`), `model_id="eos-claude"`, `first_message=""` (listen-first: any static greeting can't mirror the user's language; Claude generates every spoken reply), `platform_settings.overrides.custom_llm_extra_body=true` (without it user_token never arrives), `overrides.conversation_config_override.tts.voice_id=true` (per-user voice choice), agent auth OFF, agent default voice = ELEVENLABS_VOICE_ID. Before any PATCH, snapshot the full agent JSON to a file as a restore point.
- **Live E2E probe pattern (no app needed):** create a throwaway user via PROD signup API (id comes back in the 201 response; @example.com emails just log a harmless Resend 422), mint a token with shared SESSION_SECRET, then raw `WebSocket(signed_url)` → send `conversation_initiation_client_data` with `custom_llm_extra_body:{user_token}` + `conversation_config_override:{conversation:{text_only:true}}` (skips audio) → send `{type:"user_message",text:...}` → expect `agent_response`; answer `ping` with `pong`. Prod DB is read-only for us — the throwaway user stays (name it `voice-probe-<ts>@example.com`).
- **Disconnect symptom → cause:** agent connects, plays a generic greeting, then drops on the first real turn with NO hit in prod voice-llm logs = the agent's Custom LLM config regressed (URL/extra-body). The connection layer and our endpoint are fine; fix the agent config via PATCH.
- **Latency tuning — REVERTED after production incident (July 21, 2026):** `speculative_turn=true` + 1s soft-timeout filler ("Hhmmm...yeah") + skip_turn, live together, produced a death loop within hours: the filler spoke ~1s in (BEFORE any skip decision could arrive), Claude over-skipped short asks and speculative half-transcripts (a cut-off transcript always looks unfinished), and committed transcripts superseded speculative generations at the first word — users heard ONLY fillers while full replies appeared as text. All three are OFF (safe state: soft_timeout -1, speculative false, no skip_turn), enforced by the boot guard. Any re-tune must ensure: no filler where a skip may follow; no skip decisions on speculative transcripts; AUDIO-MODE validation. **`turn_eagerness` stays `"normal"` — DELIBERATE USER HOLD, do not raise it.** Sonnet TTFT (~0.8–1.5s on the ~13k cached prompt) is the accepted latency floor; Haiku-for-voice was rejected as a personality risk.

- **skip_turn listening (July 2026) — code ready, agent-side DISABLED after the incident:** the custom-LLM endpoint forwards ONLY allowlisted system tools to Claude (allowlist in voice-llm route — enabling a new system tool agent-side does nothing until deliberately added there) and echoes Claude tool_use back as OpenAI `tool_calls` chunks with `finish_reason:"tool_calls"`. Tool-only reply = INTENTIONAL SILENCE: no fallback line, no assistant row persisted (the "I'm here…" fallback fires only on empty text WITHOUT tool_use). **Persistence rule:** after skips the transcript arrives as CONSECUTIVE user turns — merge them for the MODEL only; persist/extract strictly the fresh utterance, or rows go cumulative. **Prompt follows the tool now:** `buildVoiceCallAddendum(hasSkipTool)` includes the LISTENING rules only when the request actually carries skip_turn — prompt and tool availability can never drift apart again; re-enable only by flipping `DESIRED_AGENT_STATE` in the guard + validated audio rollout (skip triggers need tuning first — it over-skipped short asks like "What do you think about it?").
- **Agent config guard (July 2026):** the agent is SHARED dev+prod and its config lives outside git — on production boot ONLY (`REPLIT_DEPLOYMENT`; a dev boot must never rewrite the shared agent) the api-server reconciles the agent to `DESIRED_AGENT_STATE` (services/agentConfigGuard.ts): GET → diff → minimal PATCH → verify, never throws, loud logs. Agent config changes ship WITH the code that supports them — never PATCH the live agent ahead of a publish again; that gap is how the incident happened.
- **ElevenLabs PATCH trap:** `prompt.tools: []` is SILENTLY IGNORED by the deep-merge — the no-change diff proves it. Disable a system tool by nulling `prompt.built_in_tools.<name>`; enable by setting that key to the full tool object.
- **NEVER validate voice/agent changes with text_only probes** — text_only bypasses TTS, soft-timeout fillers, speculative turn-taking, and interruption handling: exactly where this incident lived (text_only probes said "harmless" while real calls were filler-only). Minimum bar: audio-mode WS probe (no text_only override; count audio events/bytes; assert agent_response has no filler prefix). Diagnostic gold: the conversations API transcripts — `interrupted:true` flags, empty agent turns, filler-prefixed responses tell the story per turn.

## Feature flag (July 2026)
Voice Call is ON by default (`VOICE_CALL_ENABLED !== "false"`); set the var to `false` + restart the api-server only for a temporary hide — runtime env read, no rebuild. It was briefly default-OFF, which the user rejected: they want the feature visible and working, with failures explained on-screen, never hidden. Listen TTS and Mic dictation are deliberately NOT gated.
