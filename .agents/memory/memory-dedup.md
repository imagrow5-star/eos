---
name: Semantic dedup & memory reset (Sprint: dedup & reset)
description: Extraction-time + backfill semantic dedup for memory rows; founder-gated reset endpoint
---
- **The pollution bug:** extraction (`services/ai.ts`) inserted a new row every time a user restated the same intention, so the Memory Manifest showed the same thing 3–4× across facts/habits/goals/commitments. The old dedup was a crude substring match (`fact.includes(other.slice(0,20))`) — no semantic sense.
- **Extraction-time dedup** lives in `services/memory/dedup.ts` (pure + injectable). Flow per candidate: cheap lexical pre-filter (`bestLexicalOverlap`; zero shared meaningful token ⇒ skip Haiku, not a dup) → else a small Haiku call (`findSemanticDuplicate`) → on a hit, BUMP the matched row's `times_referenced`+`last_referenced_at` instead of inserting. **Fail-OPEN everywhere** (any parse/network error ⇒ "not a duplicate" ⇒ insert) so a flaky check never loses data. Wired into `extractMemory` (facts), `extractCommitments`, `detectHabitMentions` (habit name), `createGoalWithTasks` (upgrades the old exact-norm dedup). Each takes an optional `dedupFinder` so tests inject a deterministic stand-in (real Haiku isn't in CI).
- **Schema:** added `times_referenced` (int, default 1) + `last_referenced_at` (timestamp, null) to `habits`/`goals`/`commitments` (mirrors `memory_facts`' Sprint 2A columns). Additive + defaulted ⇒ legacy rows valid with no backfill. `drizzle-kit push` applies on deploy.
- **Backfill** (`services/memory/dedupBackfill.ts`): per-user, per-table (memory_facts/habits/commitments/goals), batches of 20 → Haiku clustering (`groupSemanticClusters`) → `planMerges` (PURE, unit-tested) keeps the OLDEST row as canonical, folds `times_referenced` (sum), `last_referenced_at` (max), and for facts `emotional_weight` (max) + `user_marked_important` (OR), deletes the rest. Habit completions are REPOINTED onto the keeper before its dup habits are deleted (goal_tasks cascade). Idempotent (a clean account clusters nothing). **Gated behind `DEDUP_BACKFILL_ON_BOOT=true`** — per-user Haiku calls aren't free, so the operator enables it for one deploy then unsets it; wired non-blocking in `index.ts`.
- **Reset** (`POST /api/memory/reset`, `services/memory/resetGate.ts`): founder-gated by `MEMORY_RESET_ALLOWLIST` (comma-sep emails, case-insensitive). `resetAllowlistDecision` is the single pure gate → 404 when unset (feature "doesn't exist"), 403 when email not listed, else wipe. Wipes ONLY `memory_facts/habits/habit_completions/commitments/goals/mood_scores` in one txn (messages/chapters/sealed_notes/profile/subscription KEPT), returns per-table counts. Rate-limited 1/hour (`memoryResetUsageLimits`, `MEMORY_RESET_LIMIT_PER_HOUR`). UI: `GET /api/memory/reset-eligible` → Memory Manifest renders the "Reset my memory (dev)" button + confirm modal only when eligible.
- **Privacy:** dedup/reset log sites emit `uh` (hashed userId) + table/matchingId/counts only — never candidate text or a raw userId (Tier 3 guardrail stays green).
- **Testing pattern:** the LLM's semantic judgement can't run in CI (no `ANTHROPIC_API_KEY`). Unit tests pin parsing + `planMerges` + lexical prefilter + gate; DB-gated tests inject a deterministic `DedupFinder`/`ClusterGrouper` (lexical stand-in over real ids) to prove the insert/increment/merge/delete mechanics. Extraction tests stub `messagesProto.create` for the extraction call and inject the finder for the dedup decision.
